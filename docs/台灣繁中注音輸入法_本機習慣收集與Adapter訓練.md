# 本機習慣收集與 Adapter 訓練機制

最後更新：2026-06-18

## 目標

建立一套本機、明確選擇加入、可刪除、可回退的使用者習慣收集與 adapter 訓練機制，讓輸入法能逐步學會使用者常用詞、專業領域、英文混輸習慣與候選修正模式。

這個機制不能破壞既有隱私原則：預設不連網、不上傳、不記錄輸入原文。

## 第一性原理判斷

使用者真正需要的不是「收集越多越好」，而是：

1. 降低重複修正同類候選錯誤的成本。
2. 讓使用者自己的用詞、英文片段、專業詞彙能被本機學到。
3. 不讓私人輸入內容流出裝置。
4. 出錯時可停用、刪除、回退。

因此本機習慣收集不是預設全量記錄，而是分層、最小化、可驗證的資料流程。

## 資料分層

| 層級 | 名稱 | 預設 | 是否含文字 | 用途 |
|---|---|---|---|---|
| L0 | 非內容型計數 | 開啟 | 否 | 延遲、回退次數、候選排名區間 |
| L1 | 本機修正事件 | 關閉，需明確選擇加入 | 可能含短上下文與候選 | 訓練個人 adapter、改善排序 |
| L2 | 使用者選檔語料 | 關閉，需每次明確選檔 | 是 | 使用者主動提供的本機訓練資料 |

L0 不能訓練語言 adapter，因為沒有內容訊號。L1 與 L2 才能訓練，但都必須留在本機，且可刪除。

## L1 本機修正事件

### 可收集事件

只有在使用者開啟「本機個人化學習」後才可收集：

- 使用者選了第幾候選。
- 原第一候選與最後選中候選。
- 對應注音序列。
- 有限長度上下文，例如前後各最多 12 個中文字或 24 個 ASCII 字元。
- 是否包含英文片段。
- 應用程式類別，例如編輯器、瀏覽器、通訊軟體；不記錄完整視窗標題。
- 時間桶，例如上午、下午、晚上；不記錄精確時間戳。

### 不可收集事件

- 密碼欄位、macOS Secure Input、系統標示為安全輸入的內容。
- 使用者封鎖清單中的應用程式。
- 剪貼簿內容。
- 未送出的完整長文。
- 完整視窗標題、網址、聊天對象、檔案完整路徑。
- 任何會自動上傳的內容。

## 事件最小化

每筆 L1 事件必須符合：

1. 上下文長度有上限。
2. 只保存候選重排需要的欄位。
3. 可透過設定完全關閉。
4. 可由使用者查看事件數量、資料大小、最近訓練時間。
5. 可一鍵刪除。
6. 預設保留期有限，例如 30 天或 5,000 筆事件，先到者觸發清理。

## 本機儲存

建議元件：

- `LocalUsageEventStore`
- `LocalAdapterTrainer`
- `AdapterRegistry`
- `AdapterPromotionGate`

儲存要求：

- 儲存在使用者本機應用程式資料目錄。
- 不進 repo、不進 crash report、不進一般 log。
- 可匯出摘要，但摘要不得含原文。
- 若平台支援，敏感資料使用系統保護機制，例如 macOS Keychain 或檔案保護。

## 觸發重新訓練

### 觸發條件

任一條件成立即可排入本機訓練佇列：

- 新增修正事件達到 300 筆。
- 最近一次 adapter 訓練後，錯誤修正率沒有改善。
- 使用者按下「立即重新訓練」。
- 使用者匯入 L2 本機語料。
- 每週排程且事件數量達到最低門檻。

### 不可觸發條件

以下情況不可訓練：

- 使用者未開啟本機個人化學習。
- 使用者目前正在快速打字。
- 電腦資源壓力高。
- 裝置即將關機或睡眠。
- 可用磁碟空間不足。
- 事件數低於最低門檻。

### 執行時機

- 背景低優先權。
- 不阻塞按鍵事件。
- 可取消。
- 可暫停。
- 訓練失敗不影響輸入法。

## Adapter 訓練方式

Adapter 是個人化小型調適權重，不取代基底模型。

訓練輸入：

- L1 修正事件。
- L2 使用者選檔語料。
- 合成英文混輸保護案例。
- 固定的台灣繁中保留測試集。

訓練輸出：

- adapter 權重。
- adapter manifest。
- 本機評測報告。
- 回退點。

manifest 欄位：

- adapter id。
- 基底模型 id。
- 訓練時間。
- 事件數。
- L2 語料來源摘要。
- 是否含私人資料。
- 評測分數。
- 延遲分數。
- 啟用狀態。

## 啟用前 Promotion Gate

新 adapter 不能直接啟用，必須先通過：

1. 本機保留測試集不退化。
2. 英文混輸保護不退化。
3. 使用者最近修正事件回放有改善。
4. p95 重新排序延遲不超過既有預算。
5. adapter 檔案可載入。
6. 舊 adapter 可回退。

若未通過，保留報告但不啟用。

## Shadow Mode

新 adapter 第一次通過後，建議先進 shadow mode。

Shadow mode 的行為：

- 實際候選仍使用目前穩定 scorer。
- 新 adapter 只在背景計算排名。
- 只記錄非內容型比較指標。
- 達到穩定門檻後才建議啟用。

## 使用者控制

設定頁至少需要：

- 開啟 / 關閉本機個人化學習。
- 顯示本機事件數量與資料大小。
- 顯示最近 adapter 訓練時間與狀態。
- 立即重新訓練。
- 停用個人 adapter。
- 刪除本機事件。
- 刪除 adapter。
- 應用程式封鎖清單。
- 匯入本機文字檔。

預設：

- L0 開啟。
- L1 關閉。
- L2 關閉。
- adapter 自動啟用關閉，需先通過 promotion gate 並提示使用者。

## 失敗回退

以下情況必須回退：

- adapter 不存在。
- adapter manifest 與基底模型不相容。
- adapter 載入失敗。
- adapter 推論逾時。
- adapter 評測不通過。
- 使用者關閉個人化學習。

回退目標依序為：

1. 穩定的上一版 adapter。
2. Phase 1 deterministic scorer。
3. 原本小麥注音 baseline。

## 驗收條件

1. 預設安裝後不收集 L1 / L2 內容資料。
2. 使用者開啟本機個人化學習後，L1 事件只存在本機。
3. 使用者可刪除事件與 adapter。
4. 達到訓練門檻後可背景觸發 adapter 訓練。
5. 訓練不阻塞按鍵事件。
6. 新 adapter 未通過 promotion gate 時不會啟用。
7. adapter 失敗時可回退。
8. L1 / L2 內容不進一般 log、crash report、commit、發佈包。

## 開放問題

1. L1 事件是否要保存候選文字，或只保存可還原候選的 key？
2. 上下文長度上限應是 12 個中文字、24 個 ASCII 字元，還是更短？
3. adapter 訓練應使用 LoRA 類方法、prefix adapter，還是更小的個人化排序表？
4. macOS 與 Ubuntu 的安全輸入偵測能力是否一致？
5. 使用者是否接受 shadow mode 後再建議啟用 adapter？
