## 建議方向

把專案從「在小麥注音上證明小型語言模型」改成「在既有小麥注音主機上，做出繁中使用者真的用得開心的開源注音輸入法」。

2026-08-17 產品決定：成功標準是同一位台灣繁中使用者少做重複修正，並且能安裝、能日常使用。未見過句子的正確率是回歸約束，不是下一季的主問題。

具體做法：

1. 不再自行做一套完整輸入法，也不再並行維護第二個 Fcitx5 前端。產品掛在小麥注音（macOS）與官方 fcitx5-mcbopomofo（Ubuntu）。
2. 第一個實驗只量測現況 `UserOverrideModel`（容量 500、半衰期 5400 秒、精確三節點鍵、當時不落盤）。持久化已於 2026-08-18 接上；改鍵與改半衰期仍是對照臂。
3. 公開語料 n-gram 只在現況覆寫顯示需要跨句泛化、或回歸約束被打破時才做。
4. 小型語言模型只保留為離線教師（合成歧義句、標註），不進按鍵同步路徑。
5. 評測從「對手寫 fixture 寫規則直到滿分」改成凍結 held-out、分開 ranking 錯誤與缺候選，並加入修正成本指標。

## First-principles audit

### 1. Need / constraint

- 陳述需求：做一個開源專案與產品，讓繁中使用者真的用得開心。
- 實際底層需求：同一位台灣注音使用者，在長句、同音字、專有名詞、英文混輸上少做重複修正；重開之後還記得；按鍵不卡；資料留在本機；macOS 與 Ubuntu 裝得起來。
- 是否相同：產品目標相同。完整輸入法、小型語言模型 runtime、六階段手寫 n-gram 作業，都是手段，不是需求本身。

### 2. Inherited assumption check

- 依賴的假設：上下文不足要用小型語言模型或可學習 ranker 補；自適應等於 adapter / LoRA；Ubuntu 要自做 addon。
- 是否已在本 session 驗證：否，下列觀察與假設相反。
  - 主機已有 `UserOverrideModel`（`Source/Engine/UserOverrideModel.cpp`，容量 500，半衰期 5400 秒，鍵為精確三節點路徑，行程內靜態物件，無序列化介面）。
  - 官方 Linux 版 [fcitx5-mcbopomofo](https://github.com/openvanilla/fcitx5-mcbopomofo) 已標明「記憶使用者最近選字」，本 workspace 亦有一份拷貝。
  - Prompt-only SLM、dictionary bigram、count-based ranker 已在 `docs/reports/experiments/registry.json` 被記為 promotion fail。
  - 文獻裡有效的自適應是線上詞彙／歷史 datastore，不是每人重訓一顆神經網路（Zhang et al. 2019；Jiang et al. 2022）。

### 4. Verdict

這是有效的研究方向重設，不是在原 SLM 路線上繼續加平台。

若繼續把「自適應」做成 LoRA adapter 或 prompt-only SLM，會重複文獻已排除、本倉也已反證的路徑。

### 5. Review

本檔是研究轉向文件。2026-08-17 已確認產品成功標準為 A–C（少重複修正）加可安裝日常使用；D 為回歸約束。下一刀是凍結規則並量測現況 `UserOverrideModel`。

## 本專案已經證明與尚未證明的事

已證明：

- 小麥注音 unigram 在台灣歧義句上會留下上下文錯誤（Phase 0：當時 60 例、43/60）。
- 手寫規則 scorer 能在「為它準備的句子」上把錯誤壓到接近零，延遲在 1 ms 量級。Phase 1.1 在原 60 例上 60/60；現行 saturated suite 為 100+50+84=234 例，deterministic 234/234。
- 現行 `heldout_generalization_clean` 上，hygiene 後的 unigram baseline 為 44/63，deterministic 為 63/63（`ollama_slm_smoke_2026_06_24.json`、`clean_promotion_gate.json`）。
- 英文片段必須當保護區段處理，否則會變成 missing reading。
- 評測器、candidate diagnostics、content-free report 這條實驗基礎設施可用。
- Prompt-only 本機 SLM 在格式穩定度與延遲上不能進同步路徑。
- 精確字串 count-feature ranker 對 disjoint context 沒有 override 訊號。

尚未證明：

- 真實使用者連續打字時，修正次數是否下降。Dogfood 計數器存在，實際桌面使用證據未成為決策依據。
- `UserOverrideModel` 對重複同音錯誤的命中率、跨句轉移率、重開輸入法後的保留率。
- 在規則凍結後的新句子上，統計語言模型是否優於規則。
- 台灣注音是否需要神經 emission model。PERT 的數字來自簡中新聞＋拼音＋GPU。

## 「自適應」應採用的操作定義

文獻與現有系統把自適應分成層，不應再混成一個「模型」：

| 層 | 機制 | 本專案現況 |
|---|---|---|
| A. 使用者詞 | 手動加詞／排除詞 | 小麥注音已有 |
| B. 選字覆寫記憶 | 觀察「原本第一候選 → 使用者選的字」，在相似局部上下文再出現時提升該候選 | `UserOverrideModel` 已有，但只在記憶體、500 筆、半衰期 1.5 小時、鍵為精確三節點 |
| C. 線上詞彙生長 | 使用者推翻 top-1 時，把最長 mismatch n-gram 加進個人詞表 | Zhang et al. ACL 2019；本專案未做 |
| D. 公開語料語法模型 | 字／詞 n-gram 調整格子分數 | Rime octagram 路線；本專案 dictionary bigram 已失敗，通用 5-gram 未做 |
| E. 人口規模聯合學習 | Gboard NWP + DP | 任務不同，也沒有百萬裝置 |
| F. 生成式個人化 | HuoziIME / GeneInput | 與現行 spec「模型不得擁有輸入法」衝突 |

本專案的「自適應」應先指 A–C，再用 D 補「沒見過的句子」。E、F 不列為 2026 年研究主線。

## 論文對本專案的約束

完整條目見論文調查檔。這裡只留會改變路線的結果。

1. Chen and Lee, ACL 2000：商用級轉換的骨架是 n-gram 加英文／錯字模型，不是生成模型。來源：https://aclanthology.org/P00-1031/
2. Zhang, Huang, Zhao, ACL 2019：線上更新詞彙使 People's Daily top-1 MIU 相對其 base P2C 上升 14.94 個百分點；Table 3 On-P2C(bi) ED=400 的 People's Daily top-1 為 71.3。來源：https://aclanthology.org/P19-1154/
3. Jiang, Cheng, Han, IEEE Access 2022：只存使用者歷史表示、不再訓練神經網路，跨領域 Top-1 MIU-Acc / CA / KySS 至少 +20.0 / +8.1 / +18.3。該文寫明為每位使用者線上訓練神經網路成本過高。來源：https://doi.org/10.1109/access.2022.3218337
4. PERT, 2022：Bigram 字正確率 85.10%、句正確率 34.26%；PERT-base 96.59% / 73.31%；PERT-tiny 加 Bigram 把字正確率從 85.18% 拉到 91.28%。語料為中國新聞網站經 PYPinyin 轉拼音。延遲表上 Bigram 在 CPU，PERT 在 V100。來源：https://arxiv.org/abs/2205.11737
5. Tan et al., ACL 2022：拼音約束解碼的 GPT 在完整拼音上強，縮寫拼音 P@1 從 80.22 降到 26.90。來源：https://aclanthology.org/2022.acl-long.133/
6. Hard et al., 2018：Gboard 神經 NWP 的對照組已包含使用者歷史 n-gram；聯邦學習用約 150 萬 client。來源：https://arxiv.org/abs/1811.03604
7. Shan et al., ACL 2026 Demo：HuoziIME 冷啟動 800–1700 ms、Q4 模型 485 MB、峰值記憶體約 1.12 GB、GPL-3.0。來源：https://arxiv.org/abs/2604.14159
8. Jia and Zhao, 2013：IME 評測應含 KySS／MIU，不只整句 exact。來源：https://aclanthology.org/I13-1170.pdf
9. Wu, Xiao, and Chen, IJCNLP 2013：兩個月使用者日誌挖出 6k 複合詞，top-1 / top-12 從 76.12 / 82.05 升到 79.41 / 87.82（Table 2）。覆寫／加詞這層已有編號增益。來源：https://aclanthology.org/I13-1172.pdf
10. Tokunaga, Kazama, and Torisawa, WTIM 2011：可用更正日誌做個人化；同一段寫使用者已在抱怨轉換變差，所以要有錯誤偵測閘。來源：https://aclanthology.org/W11-3502.pdf
11. Zou et al., LREC 2026：句級 GPT-4 BLEU 0.906、CER 0.047、耗時 2.649 秒；Pinyin2Hanzi DAG BLEU 0.371、<0.01 秒（Table 3）。詞級仍是 macOS Pinyin 領先（Table 2）。作者建議本機詞庫引擎加可選長上下文模型。來源：https://lrec.elra.info/lrec2026-main-337

## 診斷：先前路線把三個問題綁在一起

| 問題 | 本倉證據 | 文獻對應 | 先前做法 | 調整 |
|---|---|---|---|---|
| 已知同音功能詞（在／再、的／得） | 規則 scorer 在 saturated suite 234/234 | 商用 IME 用規則＋詞庫即可 | 繼續為每筆 heldout 加規則 | 凍結規則包，只修回歸 |
| 沒見過的句子上的同音 | heldout 未加規則前僅 41/63；count ranker 0 override | PERT／n-gram／約束解碼 | 對 heldout 寫規則直到 63/63 | 另建凍結測試集；試公開語料 n-gram |
| 同一使用者的重複修正 | `UserOverrideModel` 未納入評測；adapter 文件未實作 | Zhang 2019；Jiang 2022 | 規劃 LoRA adapter | 成功標準若為 A–C，先量測現況覆寫模型 |

`heldout_generalization_clean` 的 63/63 是規則擴充加上讀音 hygiene 之後的回歸門檻，不能再當「泛化已解決」的證據。

## 建議架構

維持 spec 原則：模型或統計層只輸出分數增量，不產生候選集外文字。

```text
按鍵
  → ReadingGrid + McBopomofoLM（unigram、使用者詞、排除詞）
  → DeterministicContextualScorer（凍結規則包）
  → UserOverrideModel（現況：行程內、500、5400 秒、精確三節點）
  → 僅在 A–C 量測顯示不足時，才擴充持久化／鍵／半衰期
  → OptionalPublicNgramScorer（公開語料，未過 gate 不進預設）
  → walk()
```

延遲預算維持：同步路徑 p95 < 2 ms；較重的 n-gram 若超過，只在送出前或停頓後執行。

隱私維持：預設不連網。A–C 層的事件留在本機，可關、可刪。公開 n-gram 的訓練語料走既有 manifest，不含使用者原文。

Ubuntu：在官方 fcitx5-mcbopomofo 上接同一組 C++ scorer，或把本 fork 的 scorer 以函式庫形式提供給該專案。停止把「自做第三個 addon」當 P0。

| K1 `head_reading` | 1/5 | 1/8 | 0 | 1（`在`→`再`） | `uom_key_k1_2026_08_18.jsonl`、`uom_key_k1_harm_2026_08_18.jsonl` |
| K2 `head_next` 加重新 suggest | 2/5 | 2/8 | 0 | 0 | `uom_key_k2_2026_08_18.jsonl`、`uom_key_k2_harm_2026_08_18.jsonl` |

K1 轉移到 `不要再說`；同句 `做事要小心` 不再命中，因為兩音節候選 `做事` 在只打了 `ㄗㄨㄛˋ` 時套不上去。K1 在獨立音節 `在吃飯` 的第一音打完時顯示 `再`，後面 `吃`／`飯` 才把期末句拉回 `在吃飯`。共享記憶同一現象見 `uom_key_k1_shared_2026_08_18.jsonl` 的 `ar-shared-harm-002`。

K2 另外轉移 `別做事`，並保住 `做事要小心`。`別在說` 三臂都仍是 `別在說`：軟覆寫輸給詞「別在」。

結論：不推 K1。不做默默回頭改字。現況三節點鍵仍是 runtime 預設。公開 n-gram 仍不開：轉移尚未完整，D 回歸也沒被打破。

### 2026-08-18 使用者決定：建議形態與持久化

計畫：`docs/adaptation_persist_and_suggestion_PLAN.md`。

- 不要在每打一個音節時，默默回頭改前面的字。那會讓組字區自己跳，使用者會煩。
- 可以有一次、有意義的多字建議：使用者接受一次就改幾個字。仍只能重排引擎已有候選，不能生出格子外的字。2026-08-18 探測：`別再說` 不是整詞候選。`--oneshot` replay：接受 `再說` 或 `做事` 一次後，`別再說`、`不要再說`、`別做事` 變對；`再說一遍` 仍是 `再說一變`。輸入中途 prefix 有害為 0。KeyHandler 尚未接線。見 `docs/reports/experiments/adaptation/uom_oneshot_2026_08_18.md`。
- 選字覆寫記憶要持久化：重開輸入法後還在。這是產品 A–C 的落盤，檔留在本機，可關、可刪。
- 持久化檔不是公開 n-gram／小型語言模型的訓練語料。後續若要用這些事件做本機訓練，走 L1 習慣事件：預設關閉、需選擇加入，見 `台灣繁中注音輸入法_本機習慣收集與Adapter訓練.md`。公開 n-gram 仍只用既有 manifest，不含使用者原文。

2026-08-18 持久化已接上。引擎 `save`／`load` 測試通過。預設 replay 的 `restart_hits` 仍為 0。加上 `--persist` 後，`adaptation_replay.jsonl` 的 `restart_hits` 為 2，與 same-key 改善數相同。runtime 檔名為使用者資料夾裡、`data.txt` 旁邊的 `user-override-model.txt`；第一次選字覆寫才會建立。刪掉該檔後，下次啟動記憶為空。macOS／Ubuntu 實機確認仍需使用者。紀錄：`docs/reports/experiments/adaptation/uom_persist_2026_08_18.md`。

新驗證 held-out（未凍結）：`Tests/fixtures/contextual_bopomofo/heldout_opendata_names_2026_08_18.jsonl` 14 句。baseline 與 deterministic 皆 9/14，失敗列相同。7307 機關名整詞覆蓋 81/16043。見 `docs/reports/experiments/adaptation/heldout_opendata_names_2026_08_18.md`。

### 第 2 步（僅在第 1 步顯示需要跨句泛化，或 D 回歸被打破時，約 3 週）：一次 n-gram 實驗

產品主線不先做本步。

不做 bigram→trigram→5-gram→KenLM 的練習階梯。一次做到：

- 公開可授權台灣繁中語料，字級 5-gram + backoff，或 KenLM 僅作離線對照。
- 訓練語料 audit 為 0 污染（此步才做）。
- 只重算候選影響的局部 window。
- 在凍結 held-out 上比：baseline、凍結 deterministic、現況 UserOverrideModel、n-gram、相加。

通過條件：

- 凍結 held-out 上 improved > regressed。
- 不退化 saturated 234。
- 同步路徑 p95 < 2 ms，否則只能放送出前。
- 授權可重現。不複製 octagram 原始碼（工程選擇；octagram 本身是 BSD-3-Clause）。

若 n-gram 也沒有淨改善：停止學習式 scorer，只交付凍結規則；A–C 則加上量測後決定是否強化的覆寫模型。

### 第 3 步（可與第 1 步後半並行）：主機 dogfood

- macOS：feature flag 開 deterministic；覆寫層先用現況，強化只在 A–C 量測之後。
- Ubuntu：官方 fcitx5-mcbopomofo 或現有 addon 擇一，以能打字並收集 L0 計數器為準。
- 指標：每 100 字候選頁翻頁、覆寫命中、覆寫後又被改回。不含原文。

### 明確延後

- Prompt-only Ollama / Qwen / Gemma 同步路徑。
- LoRA / prefix adapter，直到 A–C 層被量過且不足。
- 為剩餘 heldout 再寫一條規則。
- 自訓 n-gram 六階段作業（可當個人練習，不佔研究主線）。
- 生成式 GhostText、跨應用記憶、MCP。
- 雲端推論。

## 備選方案

### 方案 1（已選）：凍結規則 + 量測現況覆寫 + 不足時再強化；n-gram 只在需要跨句泛化時

成本低，對準文獻裡的 A–C 層，也對準本倉已存在的程式。強化覆寫（持久化／改鍵／改半衰期）只在現況量測顯示不足後才做。風險是 n-gram 對注音格子仍然沒鑑別力；那時就停在已量過的 A–C。

### 方案 2：改掛 Rime schema，用 octagram + user dict

跨平台快，語法模型現成。代價是失去小麥注音手感。octagram 本身是 BSD-3-Clause；GPL-3.0 不相容來自 Squirrel / Weasel / rime-ice。適合當對照實驗，不適合作產品主線。

### 方案 3：繼續 SLM / ranker v2 / adapter 訓練

與 2026-06 的 Phase 2 計畫連續。本倉已有三條反證，文獻也指出不該為每位使用者線上訓練神經網路。只在第 1–2 步都失敗、且錯誤分析顯示需要語義相似（而非計數重疊）時再打開。

## 已確認的產品成功標準（2026-08-17）

使用者決定：做開源專案與產品，讓繁中使用者真的用得開心。

操作定義：

| 層 | 標準 | 角色 |
|---|---|---|
| A–C | 同一位使用者少重複改同一類同音字；重開之後還記得 | 主問題 |
| 可安裝 | macOS 小麥注音與 Ubuntu fcitx5-mcbopomofo 能日常打字 | 產品約束 |
| 延遲／隱私 | 同步路徑 p95 < 2 ms；預設不連網；可關、可刪 | 產品約束 |
| D | 凍結 held-out 與 saturated 234 不退化 | 回歸約束 |

「用得開心」在出貨輸入法裡對應的是使用者詞、選字頻率、近因記憶。小麥注音已有會落盤的使用者詞；缺的是會落盤的隱性選字記憶。第一刀仍是量測現況覆寫：same-key 命中、跨句轉移、有害覆寫。轉移率接近 0 時先改鍵。有害覆寫明顯時先保留遺忘。轉移成立且有害覆寫可接受後，第一個產品增量是把現況覆寫落盤，使用者詞檔繼續當永久釘住。公開 n-gram 若要做，語料用可授權的台灣繁中來源（政府開放資料、手寫句、CC0 句）；完整 ASBC 需另外申請付費，不能當未簽約就能做的預設。不用 OpenCC 把人民日報塗成台灣文。
