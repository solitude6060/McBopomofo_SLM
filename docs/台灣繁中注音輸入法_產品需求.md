# 台灣繁中注音輸入法產品需求

最後更新：2026-06-18

## 問題定義

小麥注音已經是可用度高的本機繁中注音輸入法，但目前選字主要依賴單詞分數。連續輸入長句時，候選詞彼此缺少上下文判斷，容易出現同音字、近義詞、專有名詞、台灣用語、英文混輸片段的排序錯誤。

本專案要解決的是「降低台灣繁中注音連續輸入的修正成本」，不是把聊天模型放進候選視窗。

## 目標使用者

主要使用者：

- macOS 小麥注音使用者，平常以注音輸入台灣繁體中文。
- Ubuntu 桌面使用者，目前使用 Fcitx5、IBus、Rime、Chewing 等輸入方案，但希望有更好的台灣繁中連續選字。
- 常混用中文、英文產品名、程式識別字、命令、公司名、學術詞、金融詞的工作者。
- 在意隱私，希望輸入內容留在本機、不交給雲端服務的使用者。

非主要使用者：

- 手機鍵盤使用者。
- 主要使用倉頡、行列、嘸蝦米等字形輸入法的使用者。
- 期待雲端改寫、聊天助理、長文生成的使用者。

## 產品目標

1. 提升台灣繁中注音句子級第一候選正確率。
2. 保護英文混輸片段，例如 `API`、`GitHub`、`Dockerfile`、版本號、路徑、命令與程式識別字。
3. 保留小麥注音現有穩定行為；模型或新排序器失敗時必須退回原本結果。
4. 預設不連網、不上傳輸入內容、不記錄原文。
5. 先建立可量測的評測集與基準，再決定是否真的需要小型語言模型。
6. 允許未來自行訓練，但訓練資料、模型權重、授權與隱私需先建立清楚邊界。
7. macOS 先落地，Ubuntu 以共用評測與排序核心作為後續路線。
8. 支援明確選擇加入的本機個人化學習，收集有限修正事件並觸發 adapter 重新訓練。

## 非目標

1. MVP 不做雲端推論。
2. MVP 不改寫整個小麥注音狀態機與候選介面。
3. MVP 不讓模型自由產生候選集外文字。
4. MVP 不把使用者輸入、使用者詞庫、修正紀錄上傳。
5. 第一階段不做完整 Linux 前端。
6. 不以簡中語料、拼音任務、非台灣書面慣例作為主要訓練或調校目標。

## 使用者故事

1. 作為 macOS 注音使用者，我希望長句第一候選更符合上下文，讓我少按方向鍵與數字鍵。
2. 作為台灣使用者，我希望候選詞偏向台灣用語、地名、機構名稱與常見書面詞。
3. 作為開發者，我希望英文片段不被輸入法拆開、轉換、移位或錯誤記憶。
4. 作為 Ubuntu 使用者，我希望排序能力未來能在 Linux 桌面前端使用，而不是只綁在 macOS。
5. 作為隱私敏感使用者，我希望模型與自訓資料都在本機，且可以關閉、刪除、重設。
6. 作為維護者，我希望先用評測證明小型語言模型比簡單上下文排序更好，再承擔模型 runtime 的複雜度。
7. 作為高頻使用者，我希望輸入法能在本機學會我常選的候選、常用英文片段與專業詞彙，並在訓練後可回退。

## 功能需求

### P0：評測與基準

需求：

- 建立台灣繁中注音歧義句測試集。
- 建立英文混輸測試集。
- 使用目前小麥注音引擎重播注音序列。
- 量測句子完全正確率、字詞正確率、目標候選排名、延遲、缺讀音案例。
- 每筆測試資料都要標示來源、授權、領域、是否可散布。

驗收：

- 可用單一命令在本機產出穩定報告。
- 至少 50 句台灣繁中歧義句。
- 至少 20 句英文混輸句。
- 同一台機器重跑兩次結果一致。

### P1：輕量上下文重新排序

需求：

- 在現有候選集上調整分數，不新增任意候選文字。
- 使用透明特徵：前後詞相容性、詞長、使用者覆寫紀錄、台灣詞彙加權、領域詞庫加權。
- 英文片段預設視為保護區段，不讓排序器任意轉換。
- 可透過評測模式或實驗設定啟用。

驗收：

- 台灣繁中歧義句錯誤率相對下降至少 10%。
- 現有引擎測試不退化。
- 按鍵同步路徑新增延遲 p95 小於 2 ms。
- 英文混輸測試不比基準差。
- 不記錄輸入原文、候選文字、送出文字。

### P2：本機小型語言模型重新排序

需求：

- 模型只做候選重新排序，不負責自由生成送出文字。
- 輸入內容限縮為必要上下文與候選摘要。
- 模型輸出必須能映射回候選分數或候選排名。
- 模型逾時、載入失敗、檔案缺失時，輸入法必須退回 P1 或原本小麥注音結果。
- 需分別評測台灣繁中、泛繁中、英文混輸案例，避免平均分數掩蓋台灣用語退化。

驗收：

- 在保留測試集上，相對 P1 額外降低錯誤率至少 5%，否則延後模型導入。
- 送出前重新排序 p95 小於 20 ms，超過 30 ms 直接回退。
- 模型故障不造成文字遺失或候選介面錯亂。
- 模型使用期間不產生含原文的紀錄。

### P2.5：自行訓練與本機調適

需求：

- 建立資料 manifest，記錄來源、授權、是否可散布、台灣相關性、前處理方式。
- 支援公開語料、合成案例、使用者本機檔案三種來源，但使用者本機資料不得自動上傳或包進發佈檔。
- 支援明確選擇加入的本機修正事件收集，用於個人 adapter 訓練。
- 使用者修正事件需有保留期、數量上限、應用程式封鎖清單、刪除與停用控制。
- 達到事件數、週期排程或使用者手動要求時，可在背景觸發 adapter 重新訓練。
- 支援刪除、重設、自訓模型停用。
- 自訓模型或 adapter 不能直接變成預設 runtime，必須通過評測、延遲與回退門檻。

驗收：

- 使用者能在離線狀態下執行本機訓練或調適。
- 產出的模型有版本、資料來源、評測結果與授權狀態。
- 使用者能查看本機事件數量、資料大小、最近訓練狀態。
- 使用者能刪除本機修正事件與 adapter。
- 新 adapter 未通過 promotion gate 時不啟用。
- 缺少或損壞模型時可回退。

### P3：Ubuntu 可行性

需求：

- 抽出不依賴 macOS IMK 的評測與排序核心。
- 先做命令列 scorer，再決定 Fcitx5、IBus、Rime 或 libchewing-adjacent 路線。
- 記錄架構決策與被拒絕方案。

驗收：

- Ubuntu 可執行同一組評測。
- 已選定第一個 Linux 整合路線，並有範圍明確的實作計畫。

## 成功指標

P0：

- 產出基準報告，包含案例數、缺讀音數、正確率、候選排名與延遲。

P1：

- 台灣繁中歧義句錯誤率相對下降至少 10%。
- 英文混輸保護不退化。
- 按鍵同步新增延遲 p95 小於 2 ms。

P2：

- 相對 P1 額外錯誤率下降至少 5%。
- 送出前模型重新排序 p95 小於 20 ms。
- 記憶體占用、載入時間與故障回退可接受。

P3：

- 評測核心可在 Ubuntu 執行，且不依賴 macOS 框架。

P2.5：

- 本機習慣事件達到門檻後可觸發 adapter 訓練。
- 新 adapter 通過本機保留測試、英文混輸保護、延遲與回退測試後才可啟用。

## 隱私需求

1. 預設不連網。
2. 不記錄原始注音、候選文字、送出文字、使用者詞庫內容。
3. 允許記錄計數器、延遲桶、模型載入狀態、錯誤碼。
4. 未來若要遙測，必須另寫設計檔，且需明確選擇加入。
5. 使用者本機訓練資料必須可刪除、可重設、不可被發佈流程誤打包。
6. 本機個人化學習預設關閉；啟用後 L1 修正事件與 L2 選檔語料只能留在本機。
7. 密碼欄位、安全輸入、封鎖清單應用程式、剪貼簿內容不得被收集。

## 未決問題

1. 哪些台灣繁中公開語料可合法放入測試集？
2. 目標硬體的延遲基準應分成 Apple Silicon、Intel Mac、Ubuntu 筆電幾組？
3. Ubuntu 第一條路線應選 Fcitx5、IBus、Rime，還是與 libchewing 分開整合？
4. 小型 transformer 是否真的必要，或傳統統計 / 輕量神經排序已足夠？
5. 英文混輸、注音、繁中詞、標點要如何切分，才能避免模型干擾英文片段？
6. 本機修正事件是否保存候選文字，或只保存可還原候選的 key？
7. 個人 adapter 訓練門檻應以事件數、錯誤率、時間排程，還是使用者手動觸發為主？
