# 台灣繁中注音輸入法產品調查

最後更新：2026-06-18T18:23:04+08:00

## 產品假設

目標不是「把聊天模型放進輸入法」，而是建立一套台灣繁中注音輸入法，讓 macOS 與 Ubuntu 使用者在長句、專業詞彙、台灣用語、英文混輸情境下，少改字、少翻候選頁、少建立自訂詞。

核心價值：

1. 台灣繁中優先：用語、字形、機構名稱、地名、產品名與常見句型以台灣為主。
2. 注音優先：注音輸入是第一級輸入方式，不是從拼音或簡中模型轉接。
3. 英文混輸穩定：英文代號、程式識別字、檔案路徑、產品名稱、版本號不可被模型干擾。
4. 本機隱私：輸入內容預設不離開裝置。
5. 速度優先：每次按鍵不可等待模型推論。

## 市場觀察

### 台灣桌面作業系統

StatCounter 於 2026 年 5 月的台灣桌面作業系統資料顯示：Windows 68.66%、Unknown 17.96%、OS X 7.7%、Linux 2.97%、macOS 2.63%、Chrome OS 0.08%。來源：https://gs.statcounter.com/os-market-share/desktop/taiwan

解讀：

- macOS 與 Linux 合計不是大眾市場主流，但足以構成高價值利基市場。
- 這個產品不應以「全台灣所有使用者」為第一階段目標，而應聚焦願意安裝第三方輸入法的高頻打字者。
- Ubuntu 使用者比例小，但對開源、本機、可調整輸入法的接受度可能較高。

### 注音在台灣的重要性

Bopomofo 是台灣常用的國語注音系統，也常用於電腦與手機中文輸入。來源：https://en.wikipedia.org/wiki/Bopomofo

產品意義：

- 注音不是附屬功能，是台灣使用者的主入口。
- 若模型主要從簡體中文、拼音、或中國用語語料學習，會偏離產品核心。

## 競品與替代方案

| 類別 | 代表 | 優勢 | 弱點 | 本產品機會 |
|---|---|---|---|---|
| macOS 內建輸入法 | Apple 內建繁中注音 | 預裝、穩定、系統整合 | 不透明、不可深度調整、Ubuntu 無法使用 | 開源、本機可測、台灣用語可調 |
| 小麥注音 | McBopomofo | MIT 授權、macOS 開源、繁中注音專注 | 目前主要是 unigram 分數，長句脈絡不足 | 直接基於現有引擎加脈絡排序 |
| 酷音 / 新酷音 | libchewing、ibus-chewing、fcitx-chewing | Linux 生態成熟，注音核心知名 | 使用體驗與脈絡預測可能不足 | Ubuntu 路線可參考其前端整合 |
| Rime | librime、Squirrel、ibus-rime、fcitx-rime | 跨平台、架構模組化、可高度設定 | 設定門檻高，不是台灣 SLM 注音專用 | 可借鏡外掛與 schema 思路 |
| Fcitx5 | Fcitx5、fcitx5-chewing、fcitx5-rime | Linux / BSD 輸入法框架，支援 X11 / Wayland | 不是單一注音產品，需要引擎 | Ubuntu 前端候選路線 |
| 本機大型語言模型輸入法研究 | HuoziIME | 2026 年已有本機模型輸入法研究與展示 | Android 取向，成熟度低，GPL 風險 | 證明方向可行，但不能直接搬程式碼 |
| 手機鍵盤 | Gboard、SwiftKey、iOS 鍵盤 | 預測與個人化成熟 | 桌面支援不足，閉源或隱私信任成本 | 台灣桌面、本機開源差異化 |

## 競品結論

### 小麥注音

適合作為起點，原因：

- 授權寬鬆，MIT License 允許修改與再發佈。
- macOS 原生整合已存在。
- 程式結構清楚，Swift / Objective-C++ / C++ 分層明確。
- 現有演算法問題與目標吻合：`algorithm.md` 說明目前是 unigram 模型，不考慮上下文。

風險：

- 原專案偏 macOS，Ubuntu 不能直接沿用 Input Method Kit 架構。
- 若直接加模型到輸入法主流程，可能破壞速度與穩定性。
- 若仍使用小麥注音名稱與圖示，需要避免讓使用者誤以為是官方版本。

### Rime

適合作為架構參考，原因：

- Rime 是跨平台 C++ 輸入法引擎。
- README 明確列出語言模型與下一詞預測外掛方向。
- Linux、macOS、Windows 前端生態完整。

不建議第一階段改成 Rime：

- 本專案核心痛點是台灣繁中注音連續選字，不是建立通用輸入法平台。
- Rime 設定能力強，但對一般使用者有門檻。
- 若重寫到 Rime，會稀釋小麥注音現有 macOS 優勢。

### libchewing / Fcitx5

適合 Ubuntu 路線參考：

- libchewing 是注音核心，Fcitx5 是 Linux / BSD 輸入法框架。
- Fcitx5 README 說明其是通用輸入法框架，Linux / BSD 支援 X11 / Wayland。
- fcitx5-chewing 已存在，表示 Ubuntu 前端整合有現成生態。

不建議直接複製：

- 授權與架構不同，libchewing 是 LGPL，不能把程式碼任意併入 MIT 專案而不處理授權。
- 產品目標不是替換所有 Linux 注音方案，而是先把台灣繁中脈絡排序做好。

## 使用者價值假設

| 使用者 | 現在問題 | 願意換輸入法的條件 |
|---|---|---|
| macOS 台灣開發者 | 中文句子夾英文、套件名、命令列時常需要手動調整 | 英文片段穩定，常用技術詞彙不用一直自訂 |
| Ubuntu 台灣使用者 | 可用輸入法選擇少，注音體驗落後手機鍵盤 | 安裝不困難，Fcitx 或 IBus 下可用 |
| 研究生 / 寫作者 | 長句與專有名詞需要修正，影響思路 | 連續輸入正確率明顯提高 |
| 隱私敏感使用者 | 不想讓輸入內容進雲端 | 本機、不連網、可關閉模型 |
| 重度小麥注音使用者 | 小麥比酷音順，但長句選字仍不夠聰明 | 保留小麥手感，只改善排序 |

## 產品差異化

1. 台灣繁中資料與評測優先，而非泛中文模型。
2. 注音候選重新排序，而非生成式聊天輸入。
3. 英文混輸保護，適合開發者與知識工作者。
4. 本機與可關閉，降低輸入法隱私風險。
5. 先評測後導入模型，避免模型成為速度負擔。

## MVP 建議定位

名稱暫定：台灣繁中注音脈絡排序器。

第一版不承諾「人工智慧輸入法」，而是承諾：

- 小麥注音手感不變。
- 長句選字更少錯。
- 英文混輸不干擾。
- 不連網。
- 可關閉、可回退。

## 產品風險

| 風險 | 影響 | 緩解 |
|---|---|---|
| 模型推論太慢 | 使用者覺得打字卡頓 | 模型不進按鍵同步路徑，逾時回退 |
| 訓練資料偏簡中或中國用語 | 候選字偏離台灣用法 | 台灣資料清單、台灣測試集、語料審查 |
| 英文片段被錯誤處理 | 開發者無法接受 | 英文片段保護與專門評測 |
| 使用者不信任輸入法隱私 | 不願安裝 | 預設不連網、無內容型紀錄、公開說明 |
| Ubuntu 需求變成重寫輸入法 | 時程失控 | 先做可攜式評測與核心，不先做 Linux 介面 |
| 授權混入 GPL 程式碼 | 影響發佈授權 | GPL 專案只參考，不複製；所有來源建 manifest |

## 待驗證假設

1. 小麥注音錯誤是否主要來自上下文不足，而不是詞庫缺漏？
2. 台灣繁中使用者最在意的是長句選字、英文混輸、還是專有名詞？
3. 使用者能接受模型只在送出前或停頓後改善候選，而不是每鍵即時改善嗎？
4. 自行訓練是否是核心需求，或只是進階使用者功能？
5. Ubuntu 使用者偏好 Fcitx5、IBus、Rime，還是命令列 / 編輯器整合？

## 建議決策

先不要把小型語言模型當成第一個可見功能。第一個可見功能應該是：

1. 台灣繁中歧義句評測集。
2. 英文混輸保護。
3. 輕量脈絡重新排序。
4. 本機模型重新排序實驗。
5. 自行訓練工具。

只有當第 4 項明確勝過第 3 項，才把模型放進可開啟的實驗功能。
