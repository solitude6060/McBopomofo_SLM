# 台灣繁中注音輸入法 MVP 路線圖

最後更新：2026-06-18

## MVP 判準

MVP 成功不是「模型跑在輸入法裡」，而是以本機評測與實際使用證明：上下文重新排序能降低注音連續輸入修正成本，同時不犧牲速度、隱私、穩定性與回退能力。

## Phase 0：真實案例與基準

期間：1 到 2 週。

交付：

- 台灣繁中注音歧義句測試集。
- 台灣用語與英文混輸測試集。
- 現有小麥注音引擎重播工具。
- 基準報告：句子正確率、字詞正確率、候選排名、延遲、缺讀音。
- 語料與測試資料授權決策紀錄。

退出條件：

- 至少 50 句台灣繁中歧義案例。
- 至少 20 句英文混輸案例。
- 基準報告可重現。
- 目前錯誤類型已依頻率排序。

決策：

- 若錯誤主要來自詞庫缺漏，先補詞庫。
- 若錯誤主要來自上下文選字，進入 Phase 1。

## Phase 1：輕量上下文重新排序

期間：2 到 4 週。

交付：

- `ContextualScorer` 介面。
- `DeterministicContextualScorer` 實作。
- 評測模式與實驗設定。
- 英文片段保護。
- 使用者覆寫與回退測試。
- 基準對照報告：原始小麥注音 vs P1 重新排序。

退出條件：

- 台灣繁中歧義句錯誤率相對下降至少 10%。
- 現有 C++ 引擎測試不退化。
- 新增延遲 p95 小於 2 ms。
- 英文混輸案例不退化。
- 紀錄中沒有輸入原文或候選文字。

決策：

- 若 P1 已滿足主要使用場景，模型延後。
- 若 P1 改善不足且錯誤仍是上下文問題，進入 Phase 2。

## Phase 2：訓練資料與本機小型語言模型實驗

期間：3 到 5 週。

交付：

- 台灣繁中語料 manifest。
- 注音讀音產生與缺讀音報告。
- 英文區段標記規則。
- 公開語料、合成案例、使用者本機檔案的自訓實驗計畫。
- 至少一個本機小型語言模型與 P1 的離線比較。
- 候選受限的 prompt 或 scoring protocol。
- 輸入法外部的逾時與回退 prototype。
- 模型授權、大小、包裝評估。

退出條件：

- 小型語言模型相對 P1 額外錯誤率下降至少 5%。
- 台灣繁中與英文混輸保留測試集不退化。
- 送出前重新排序 p95 小於 20 ms。
- 模型失敗可回退，且不影響一般輸入。
- 訓練、驗證、測試切分已依來源分開。

決策：

- 未達門檻時，不把模型放進輸入法 runtime。
- 達門檻時，才進入 macOS 實驗整合。

## Phase 2.5：本機自訓工具

期間：2 到 4 週，僅在 Phase 2 顯示價值後啟動。

交付：

- 使用者本機文字檔訓練命令。
- 明確選擇加入的本機修正事件收集。
- adapter 重新訓練觸發器。
- promotion gate 與 shadow mode。
- 資料刪除與重設流程。
- 模型 manifest：來源、tokenizer、模型版本、評測結果。
- 防止本機私有資料進入紀錄、commit、發佈包的檢查。

退出條件：

- 使用者可離線訓練或調適模型。
- 使用者可開啟本機個人化學習，累積修正事件並觸發 adapter 訓練。
- 產出的模型或 adapter 可啟用、停用、移除。
- 新 adapter 未通過 promotion gate 時不啟用。
- 模型缺失或無效時永遠回退。

## Phase 3：macOS 實驗 runtime

期間：3 到 5 週。

交付：

- 實驗設定開關。
- 本機 scorer 整合到 macOS 輸入法。
- 停用、逾時、模型缺失、模型錯誤時的回退路徑。
- 實際使用檢查表與錯誤回報格式。

退出條件：

- 使用者可不重裝就啟用或停用。
- 候選介面行為與小麥注音一致。
- 紀錄中沒有輸入原文。
- 定義期間內一般打字不崩潰。

## Phase 4：Ubuntu 可行性

期間：2 到 4 週。

交付：

- 評測與排序核心可在 Linux 編譯執行。
- 選擇 Fcitx5、IBus、Rime 或其他路線的架構決策紀錄。
- Ubuntu 命令列轉換 demo。

退出條件：

- 同一組評測可在 Ubuntu 跑。
- Linux 整合路線與範圍明確。

## Phase 5：公開 alpha

期間：Phase 0 到 4 完成後 4 到 6 週。

交付：

- macOS alpha 安裝包。
- 評測摘要。
- 隱私說明。
- 已知限制。
- 停用與移除方式。

退出條件：

- 使用者可安裝、啟用、停用、移除。
- 發佈說明包含正確率、延遲、模型大小、限制。
- 無雲端行為。

## 里程碑決策表

| 閘門 | 繼續條件 | 停止或轉向條件 |
|---|---|---|
| Phase 0 後 | 錯誤可量測，且主要是上下文歧義 | 主要是詞庫缺漏或非上下文問題 |
| Phase 1 後 | P1 低延遲且改善明確 | 改善小或破壞使用者覆寫 |
| Phase 2 後 | 模型明顯優於 P1 且符合延遲 | 模型慢、不穩、或英文混輸退化 |
| Phase 3 後 | 實際使用者修正成本下降 | 使用者因延遲、候選意外、穩定性而停用 |
| Phase 4 後 | Linux 核心可用且前端路線清楚 | Ubuntu 需要重做成另一個產品 |

## 待辦清單

- 個人本機詞語記憶與重設控制。
- coding、金融、學術、訊息等領域設定檔。
- 從大型教師模型蒸餾成小型排序模型。
- 台灣地名、機構、產品、流行詞更新包。
- 本機自訓使用者風格模型。
- debug build 的候選解釋模式。
- Rime schema 實驗，服務偏好 Rime 前端的使用者。

## 主要風險

1. 小型語言模型可能不比 P1 透明特徵好。
2. 模型 runtime 可能增加啟動時間、記憶體與崩潰風險。
3. 可散布的台灣繁中語料不足。
4. 泛繁中語料可能帶入非台灣用語偏好。
5. 自訓可能保留敏感詞，需嚴格處理刪除、紀錄、發佈邊界。
6. Ubuntu 可能變成獨立前端專案，不能視為簡單移植。
7. 離線正確率提高，不一定代表使用者感受改善；實際使用仍需驗證。
