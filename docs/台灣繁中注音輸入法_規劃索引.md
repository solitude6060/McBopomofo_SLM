## 目前結論

1. 產品定位：台灣繁中注音輸入法，不是泛中文輸入法，也不是寫作助理。
2. 第一價值：降低連續注音輸入時的選字修正成本。
3. 速度原則：每次按鍵同步路徑不可等待小型語言模型；模型只能在背景、停頓後、送出前、或離線訓練路徑使用。
4. 隱私原則：預設不連網、不上傳輸入內容、不記錄原文輸入。
5. 技術路線：先建立評測，再做輕量脈絡重新排序，最後才決定是否導入本機小型語言模型或自行訓練模型。
6. 本機個人化：使用者習慣收集必須明確選擇加入；L1 修正事件與 L2 選檔語料只能留在本機，可刪除、可停用、可回退。
7. 授權結論：修改小麥注音本體大致可行，主要風險在 GPL 程式碼借用、模型權重、訓練資料、品牌識別與重新發佈合規。
8. Phase 0 已完成：`docs/reports/phase0_baseline_report.md` 顯示 60 例台灣歧義句中 43 例完全正確，句子正確率 71.67%，CJK token accuracy 94.95%，17 個錯誤皆屬 context ambiguity。
9. Phase 1 evaluator-only 進度：`docs/reports/phase1_reranker_report.md` 顯示台灣歧義句 53/60，句子正確率 88.33%，錯誤相對 Phase 0 下降 58.82%；英文 mixed missing reading 已由 25/25 降為 0/25，但 exact 仍只有 9/25。
10. Phase 1 決策：先補 scorer unit tests、evaluator regression tests、fixture reading audit，不直接導入 SLM runtime。

## 下一步

1. 補 `DeterministicContextualScorer` 單元測試，鎖定 score delta、非重疊 correction、protected-English 規則邊界。
2. 補 evaluator regression tests，確認 `--reranker`、passthrough、baseline 模式可重現。
3. Audit `taiwan_ambiguous` 與 `english_mixed` 的 expected/readings：先修資料問題，再判斷是否需要更多規則或 SLM。
4. Phase 3 前才把 P1 scorer 接進 macOS runtime，並加 feature flag 與回退。
