# 台灣繁中注音輸入法需求收集

最後更新：2026-06-18T18:23:04+08:00

## 需求收集目標

確認台灣繁中注音使用者真正需要改善的是什麼，避免直接假設「加小型語言模型」就是正解。

要回答的問題：

1. 使用者目前在哪些句子、詞彙、情境下最常改字？
2. 錯誤主要是詞庫缺漏、候選排序、英文混輸、還是使用者習慣未學到？
3. 使用者對打字速度的最低要求是什麼？
4. 使用者能接受哪些本機模型行為？不能接受哪些？
5. 自行訓練對目標使用者是否重要？需要做到什麼程度？

## 目標訪談對象

第一輪建議 8 到 12 人：

| 類型 | 人數 | 條件 |
|---|---:|---|
| macOS 小麥注音使用者 | 3 | 每天用注音輸入繁中，願意描述錯字案例 |
| Ubuntu 注音使用者 | 2 | 使用 Fcitx、IBus、Rime、Chewing 任一方案 |
| 開發者 / 工程師 | 2 | 中文句子常夾英文、程式識別字、命令 |
| 長文寫作者 | 2 | 寫筆記、論文、文章、企劃、報告 |
| 隱私敏感使用者 | 1 | 明確在意輸入內容不上傳 |
| 自行訓練潛在使用者 | 1 到 2 | 願意提供個人語料或專業領域語料本機訓練 |

## 訪談問題

### 基本使用情境

1. 你現在主要用哪個作業系統與輸入法？
2. 你一天大約打多少中文？主要打在哪些應用程式？
3. 你常打的是聊天、筆記、程式檔案、論文、商務信件，還是其他內容？
4. 你的文字中英文混輸比例大約多少？

### 錯字與修正成本

1. 最近一週你記得最煩的選字錯誤是什麼？
2. 常錯的是單字、雙字詞、長句、專有名詞，還是英文混輸？
3. 錯字通常要怎麼修？選候選、退回重打、加入自訂詞，還是乾脆換句話？
4. 如果候選第一順位變準，但偶爾候選順序變動，你是否能接受？

### 台灣用語

1. 你是否遇過輸入法偏向非台灣用語？
2. 哪些詞最需要台灣化？政府機關、地名、學術詞、科技詞、生活用語、流行語？
3. 你是否需要領域詞庫，例如程式、投資、醫療、法律、學術？

### 英文混輸

1. 你常輸入哪些英文片段？例如 API、GitHub、Docker、Python、ETF、AI、公司名稱、產品名。
2. 你希望輸入法如何處理英文片段？保持原樣、候選建議、大小寫記憶、或自動補全？
3. 哪些英文片段被輸入法干擾會讓你立刻關掉功能？

### 速度

1. 你能接受候選字出現慢一點嗎？大約多少會覺得卡？
2. 如果模型只在你停頓或按空白時改善候選，而不是每按一鍵都改善，你能接受嗎？
3. 如果模型偶爾逾時並退回原本小麥注音結果，你能接受嗎？
4. 你比較在意「永遠快」還是「偶爾慢一點但更準」？

### 隱私與訓練

1. 你能接受輸入內容上傳到雲端換取更準嗎？
2. 你能接受只在本機紀錄常用詞與修正紀錄嗎？
3. 你是否願意選幾個本機文字檔讓模型學你的用字？
4. 你是否需要一鍵清除個人化資料？
5. 自行訓練時，你能接受命令列工具，還是必須有圖形介面？
6. 你能接受輸入法在本機保存短上下文與候選修正事件，用來訓練個人 adapter 嗎？
7. 哪些應用程式你絕對不希望被個人化學習收集？例如瀏覽器、通訊軟體、密碼管理器、工作軟體。
8. 你希望個人 adapter 自動啟用，還是通過測試後詢問你再啟用？

## 需求分類

| 類別 | 需求 | 重要性 | 初步方案 |
|---|---|---:|---|
| 速度 | 按鍵不可卡頓 | 必須 | 模型不進同步路徑 |
| 台灣用語 | 候選偏台灣詞 | 必須 | 台灣詞庫與台灣測試集 |
| 連續選字 | 長句第一候選更準 | 必須 | 脈絡重新排序 |
| 英文混輸 | 英文片段保持穩定 | 必須 | 保護英文片段 |
| 隱私 | 預設不連網 | 必須 | 本機推論與本機訓練 |
| 可回退 | 模型錯誤不影響輸入 | 必須 | 逾時與關閉開關 |
| 自行訓練 | 使用者可用本機資料調整 | 重要 | 離線訓練工具 |
| 本機個人化 | 修正事件可觸發 adapter 訓練 | 重要 | 明確選擇加入、保留期、刪除、promotion gate |
| Ubuntu | Linux 桌面可用 | 重要 | 先做核心評測，再選 Fcitx5 / IBus |
| 說明 | 使用者知道模型做什麼 | 重要 | 隱私與模型狀態頁 |

## 需求優先順序

### 第一階段必須做

1. 建立台灣繁中注音錯誤案例集。
2. 建立英文混輸案例集。
3. 量測現有小麥注音速度與正確率。
4. 設計不可阻塞按鍵的重新排序架構。
5. 設計隱私與紀錄邊界。

### 第二階段應該做

1. 輕量脈絡重新排序。
2. 台灣詞彙與專有名詞補強。
3. 模型送出前重新排序實驗。
4. 自行訓練資料格式與本機訓練命令。

### 暫不做

1. 雲端推論。
2. 每次按鍵呼叫小型語言模型。
3. 生成式長文補全。
4. 直接複製 GPL 專案程式碼。
5. 一開始就做完整 Ubuntu 圖形介面。

## 使用者故事

1. 作為台灣 macOS 注音使用者，我希望連續輸入長句時第一候選更準，讓我少按方向鍵與數字鍵。
2. 作為開發者，我希望 `Dockerfile`、`GitHub Actions`、`uv sync`、`API` 等英文片段不被輸入法干擾。
3. 作為 Ubuntu 使用者，我希望未來能在 Fcitx5 或 IBus 下使用同樣的台灣繁中排序能力。
4. 作為隱私敏感使用者，我希望輸入內容不會傳到雲端，錯誤紀錄也不含原文。
5. 作為進階使用者，我希望能用自己的本機檔案訓練個人模型，並能隨時刪除。

## 需求風險

| 風險 | 說明 | 需求處理 |
|---|---|---|
| 使用者說想要模型，但其實只需要詞庫 | 可能過度設計 | 訪談必須收集具體錯誤案例 |
| 使用者接受準確率提升但不接受延遲 | 模型價值被速度抵消 | 速度需求列為阻擋條件 |
| 自行訓練造成隱私外洩 | 本機檔案可能被誤打包或記錄 | 訓練資料禁止進紀錄與 release |
| 台灣用語資料不足 | 模型學到泛繁中或簡中偏好 | 建立台灣專屬評測與資料 manifest |
| Ubuntu 與 macOS 行為不一致 | 使用者跨平台體驗差 | 核心評測與排序邏輯可攜化 |

## 下一步訪談任務

1. 找 3 位小麥注音使用者，收集 20 個錯字案例。
2. 找 2 位 Ubuntu 注音使用者，確認目前輸入法與痛點。
3. 找 2 位英文混輸重度使用者，收集英文片段保護需求。
4. 找 1 位願意自行訓練的使用者，測試本機語料匯入接受度。
5. 把訪談案例轉成評測 fixture，不先寫模型。
