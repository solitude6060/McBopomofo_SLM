## 注意

這份檔案是工程與產品決策用的授權風險盤點，不是法律意見。若要公開發佈、商業化、收費、上架 App Store、或散布模型權重，仍應請熟悉開源授權、資料授權與個資法的律師確認。

## 初步結論

1. fork 小麥注音並修改程式本體，依目前 repo 內 `LICENSE.txt` 的 MIT License，原則上可行。
2. 必須保留原作者 copyright 與 MIT 授權文字。
3. 不應讓使用者誤以為 fork 是小麥注音官方版本；若公開發佈，建議改名、改 bundle identifier、改圖示或清楚標示 fork。
4. 不能直接複製 GPL 專案程式碼到 MIT 發佈的程式中，除非接受整體授權義務變化。
5. 模型權重、訓練資料、詞庫資料的授權比小麥注音本體更容易出問題。
6. 使用者自行訓練涉及個人資料與敏感文字，必須預設本機、不上傳、可刪除。
7. 本機修正事件與個人 adapter 可能含私人輸入習慣，預設不得收集，啟用後也不得進一般紀錄、commit、crash report 或公開發佈包。

## 模型權重授權

模型權重不是單純程式碼依賴。即使 runtime 是 MIT，模型本身仍有自己的授權。

初步候選：

| 模型 / runtime | 外部資訊 | 風險 |
|---|---|---|
| llama.cpp | MIT，支援本機 C/C++ 推論與量化 | runtime 低風險；實際模型另算 |
| Qwen3 | README 寫 open-weight models under Apache 2.0 | 需確認目標權重所在 Hugging Face repo 的 license 檔 |
| 其他 Hugging Face 模型 | 各模型不同 | 必須逐一確認商用、再散布、衍生模型、資料使用限制 |
| 自訓模型 | 取決於訓練資料、基底模型與輸出授權 | 必須建立 manifest |

模型發佈前最低要求：

1. 記錄基底模型名稱、版本、下載來源、license。
2. 記錄訓練資料來源、license、是否可再散布。
3. 記錄是否允許商用與再散布。
4. 若模型由使用者本機訓練，不要把個人模型放進公開 release。

## 訓練資料授權

這是最大風險區。

本專案另以 `docs/台灣繁中注音輸入法_台灣語料路線.md` 維護語料來源矩陣。初步原則：

- 教育部國語辭典公眾授權資料採 CC BY-ND 3.0 TW，適合讀音、詞彙、歧義種子；不直接把釋義全文改作成訓練語料。
- g0v `moedict-data` 是教育部資料的機器可用格式，底層內容仍依教育部授權，格式轉換部分另計。
- 政府資料開放授權資料可作 benchmark 與訓練候選，但需顯名，並逐資料集確認個資與第三方權利。
- Taiwan.md 採 CC BY-SA 4.0，適合作台灣詞彙發現與相容授權的 benchmark 候選；訓練可散布模型前需確認 share-alike 義務。
- TMMLU+ 與 DRCD 可作輔助評測或泛繁中壓力測試；是否進訓練需逐一確認 dataset card、license 與用途。
- 使用者本機資料與本機修正事件只能做本機 adapter，不進 release。

資料分級：

| 等級 | 可用性 | 例子 | 發佈限制 |
|---|---|---|---|
| A | 可散布、授權明確 | 開放授權語料、政府開放資料 | 可納入公開訓練或測試，仍需保留來源 |
| B | 可本機使用，不可再散布 | 使用者自選檔案、部分網站資料 | 僅本機訓練，不進 release |
| C | 授權不明 | 網頁抓取、論壇貼文、聊天紀錄 | 不納入訓練 |
| D | 敏感或個資 | 私訊、信件、工作檔案、病歷、財務資料 | 預設禁止，除非使用者明確本機匯入且可刪除 |

訓練資料 manifest 必填：

- 資料名稱。
- 來源網址或本機來源類型。
- 授權。
- 是否可再散布。
- 是否含個資。
- 是否台灣繁中。
- 是否經簡繁轉換。
- 用於訓練、驗證、測試哪一段。
- 建立時間。

## 個資與隱私

輸入法會看到高度敏感內容。即使沒有雲端，也要避免本機紀錄造成外洩。

最低要求：

1. 預設不連網。
2. 預設不記錄原文輸入、候選字、送出文字。
3. 錯誤紀錄只能包含耗時、逾時、模型版本、回退狀態等非內容資訊。
4. 使用者自行訓練必須明確選檔。
5. 使用者可刪除個人化資料與模型。
6. release 打包流程必須排除使用者本機資料。
7. 本機個人化學習必須明確選擇加入。
8. 本機修正事件需有保留期、數量上限、應用程式封鎖清單與刪除控制。
9. 個人 adapter 應視為使用者私有資料，不得隨公開發佈包散布。

## 品牌與發佈

MIT License 允許修改與散布，但不代表可以讓使用者誤認為官方版本。

建議：

- 專案名稱使用新名稱，例如「Taiwan Bopomofo SLM」或另取中文名稱。
- README 清楚寫「基於 McBopomofo fork」。
- bundle identifier 改成自己的識別字。
- 圖示與安裝器文字避免與官方小麥注音混淆。
- 保留原授權與 acknowledgement。
- 若仍使用「小麥注音」字樣，只作為來源描述，不作為產品主品牌。

## macOS 與 Ubuntu 平台條款

### macOS

可能涉及：

- Apple Developer Program License Agreement。
- notarization 與簽章。
- Input Method Kit 限制。
- 若上架 App Store，還會有 App Store Review Guidelines。

目前尚未逐條確認 Apple 條款；在公開散布 macOS 安裝包前，必須確認：

1. 輸入法 extension / app bundle 的簽章與 notarization 要求。
2. 是否允許下載或載入外部模型檔。
3. 是否允許本機訓練產生模型檔。
4. 隱私揭露文字是否足夠。

### Ubuntu

可能涉及：

- Debian / Ubuntu 套件政策。
- Fcitx5 / IBus / Rime / libchewing 相依套件授權。
- 若使用 LGPL library，需保留使用者替換 library 的可能性與授權義務。

## 目前判斷

用小麥注音作為基礎是合理的。真正需要嚴格控管的是：

1. 不要把 GPL 輸入法專案的程式碼直接合進來。
2. 不要使用授權不明的語料訓練可散布模型。
3. 不要把使用者私人輸入或自行訓練資料納入 release。
4. 不要讓 fork 的品牌與官方小麥注音混淆。
5. 不要在未確認平台條款前承諾 App Store 或正式套件庫發佈。
6. 不要在預設狀態保存本機修正事件；adapter 必須視為使用者私有產物。
