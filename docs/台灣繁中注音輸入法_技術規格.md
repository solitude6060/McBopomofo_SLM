# 台灣繁中注音輸入法技術規格

最後更新：2026-06-18

## 設計原則

模型不能接管輸入法。第一階段只能重新排序現有引擎產生的候選，不能自由產生送出文字。

必須保留：

- `ReadingGrid` 既有組字與走訪行為。
- 使用者詞庫與排除詞語意。
- 使用者覆寫候選行為。
- 英文混輸片段穩定性。
- 停用或失敗時的 deterministic fallback，也就是可重現的原本小麥注音結果。

## 現有架構觀察

本地檔案重點：

- `algorithm.md` 說明現有語言模型以 unigram 為主，缺少上下文。
- `Source/Engine/McBopomofoLM.cpp` 的 `getUnigrams()` 會合併主詞庫、使用者詞、排除詞、替換、巨集與轉換結果。
- `Source/Engine/gramambular2/reading_grid.h` 的 `ReadingGrid::WalkResult` 已含 `elapsedMicroseconds`，可作為基準延遲量測起點。
- `Source/Engine/gramambular2/reading_grid.cpp` 負責候選節點與最佳路徑走訪。
- `Source/LanguageModelManager.mm` 是 Swift 與 C++ 語言模型之間的橋接點。

推論：小型語言模型不應繞過 `getUnigrams()`，否則會破壞使用者詞、排除詞、替換與巨集既有語意。較合理的插入點是在候選產生後、路徑評分前後加入 score delta。

## 元件設計

### `ContextualScorer`

C++ 介面，負責可選的上下文分數調整。

責任：

- 接收有限長度的注音序列、候選、游標位置、上一段已送出文字、英文保護區段。
- 回傳分數差值，不回傳任意送出文字。
- 呼叫端負責逾時、取消、回退。

概念介面：

```cpp
struct CandidateScoreInput {
  std::string reading;
  std::string value;
  std::string rawValue;
  double baseScore;
  size_t start;
  size_t length;
};

struct ContextualScoreRequest {
  std::vector<std::string> readings;
  std::vector<CandidateScoreInput> candidates;
  std::string previousCommittedText;
  std::vector<std::string> protectedEnglishSpans;
  size_t cursor;
};

class ContextualScorer {
 public:
  virtual ~ContextualScorer() = default;
  virtual std::vector<double> scoreDeltas(
      const ContextualScoreRequest& request) = 0;
};
```

### `DeterministicContextualScorer`

P1 使用，無模型 runtime 依賴。

特徵：

- 詞語轉移統計。
- 詞長先驗。
- 使用者覆寫頻率與時間近度。
- 本機領域詞庫加權。
- 台灣用語、地名、機構、常見書面詞加權。
- 英文片段保護。
- 當多字詞與上下文吻合時，降低不相容單字候選分數。

### `LocalSLMContextualScorer`

P2 使用，需通過評測門檻才進入 runtime。

要求：

- 本機模型檔案。
- 上下文長度有上限。
- 輸出限縮為候選排名或候選分數。
- 台灣繁中、泛繁中、英文混輸分開評測。
- 逾時必須回退。
- 不產生含原文的紀錄。
- 可採 lazy loading，必要時放入獨立 helper process 降低輸入法主行程穩定性風險。

待評估 runtime：

- llama.cpp：C/C++、MIT、量化模型與 Apple Silicon / CPU 路線成熟，跨平台較合理。
- Core ML：macOS 整合佳，但 Ubuntu 路線較弱。
- ONNX Runtime：跨平台，但模型轉換與包裝複雜度較高。

### `LocalUsageEventStore`

P2.5 使用，負責保存使用者明確選擇加入後的本機修正事件。

要求：

- 預設關閉。
- 只存在本機。
- 有保留期與數量上限。
- 支援應用程式封鎖清單。
- 不收集密碼欄位、Secure Input、剪貼簿、完整視窗標題、網址或完整檔案路徑。
- 可刪除、可停用、可重設。

事件概念格式：

```json
{
  "event_id": "local-usage-0001",
  "event_type": "candidate_override",
  "readings": ["ㄊㄞˊ", "ㄨㄢ"],
  "baseline_candidate": "抬彎",
  "selected_candidate": "台灣",
  "candidate_rank": 3,
  "context_before": "我住在",
  "context_after": "",
  "has_english_span": false,
  "app_category": "editor",
  "time_bucket": "evening"
}
```

### `LocalAdapterTrainer`

P2.5 使用，負責用 L1 本機修正事件與 L2 使用者選檔語料訓練個人 adapter。

要求：

- 背景低優先權。
- 可取消。
- 不阻塞按鍵事件。
- 產生 adapter manifest。
- 訓練失敗不影響輸入法。
- 新 adapter 通過 promotion gate 後才可啟用。

觸發條件：

- 新增修正事件達到門檻，例如 300 筆。
- 使用者手動按下重新訓練。
- 使用者匯入本機語料。
- 週期排程且事件數達最低門檻。

promotion gate：

- 台灣繁中保留測試不退化。
- 英文混輸保護不退化。
- 最近修正事件回放有改善。
- p95 延遲符合預算。
- adapter 可載入。
- 舊 adapter 可回退。

## 速度模型

### 同步按鍵路徑

允許：

- 注音解析。
- 詞庫查詢。
- `ReadingGrid` 更新。
- 極輕量 deterministic score delta。

禁止：

- 等待小型語言模型。
- 大量磁碟讀寫。
- 網路請求。
- 會造成候選介面停頓的模型載入。

### 暫停或送出前路徑

允許：

- 可取消的小型語言模型重新排序。
- 有逾時的候選重排。
- 與目前組字狀態版本綁定，過期結果丟棄。

初始預算：

| 路徑 | 目標 | 硬性上限 |
|---|---:|---:|
| P1 按鍵同步重新排序 | p95 小於 2 ms | p99 小於 5 ms |
| P2 送出前模型重新排序 | p95 小於 20 ms | 超過 30 ms 回退 |
| 模型載入 | 不阻塞第一次按鍵 | 可背景載入 |
| P2.5 adapter 訓練 | 不在打字同步路徑 | 背景低優先權、可取消 |

## 評測工具

輸入格式：

```json
{
  "id": "ambiguous-001",
  "readings": ["ㄓㄜˋ", "ㄕˋ", "ㄧˊ", "ㄍㄜ˙", "ㄘㄜˋ", "ㄕˋ"],
  "expected": "這是一個測試",
  "protected_english_spans": [],
  "domain": "general"
}
```

輸出格式：

```json
{
  "engine": "baseline-unigram",
  "cases": 50,
  "exact_sentence_accuracy": 0.72,
  "token_accuracy": 0.91,
  "candidate_rank_mean": 1.8,
  "latency_microseconds_p50": 320,
  "latency_microseconds_p95": 900,
  "missing_reading_cases": 0,
  "english_span_preservation_accuracy": 1.0
}
```

## 訓練管線

自行訓練可以做，但必須與輸入法 runtime 分開。

必要階段：

1. 語料 manifest：來源、網址、授權、是否可散布、台灣相關性、前處理方式。
2. 台灣繁中標準化：若使用 OpenCC 類工具，需人工檢查區域詞差異。
3. 注音讀音產生：使用現有詞庫能處理者先轉，不能處理者記為 missing reading。
4. 候選集產生：使用目前引擎產生候選，讓訓練任務貼近 runtime。
5. 英文區段標記：產品名、命令、路徑、版本號、程式識別字。
6. 訓練、驗證、測試切分：以來源與文章切分，不只用句子切分，降低資料洩漏。
7. 與 unigram 基準、P1 重新排序器、候選 oracle rank 比較。
8. 本機修正事件訓練個人 adapter 時，需先做事件去識別化、長度截斷、封鎖清單過濾與保留期清理。

模型升級門檻：

- 在保留測試集上優於 P1。
- 台灣繁中與英文混輸都不能退化。
- 延遲與記憶體符合預算。
- 模型權重可合法散布，或提供使用者本機重建路線。
- 個人 adapter 必須通過本機 promotion gate，且可回退到上一版 adapter 或 P1 scorer。

## 紀錄規則

允許：

- 計數器。
- 延遲桶。
- 回退次數。
- 模型載入狀態。
- 錯誤碼。
- 使用者明確選擇加入後的本機修正事件，但只能存於本機個人化資料庫，不得進一般 log。

禁止：

- 原始注音。
- 候選文字。
- 已送出文字。
- 使用者詞庫內容。
- 模型 prompt 與輸出。
- 使用者本機訓練檔案內容。
- 密碼欄位、安全輸入、剪貼簿內容、完整視窗標題、網址、完整檔案路徑。

## 測試策略

1. 單元測試：score delta、英文保護、逾時回退、使用者覆寫優先權。
2. 整合測試：讀入注音序列、產生候選、重新排序、回傳結果。
3. 基準測試：p50、p95、p99 延遲，分別量測基準、P1、P2。
4. 回歸測試：現有小麥注音測試必須通過。
5. 隱私測試：確認紀錄中沒有原文、候選、使用者詞庫內容。
6. 個人化測試：確認 L1 預設關閉、開啟後只存本機、刪除有效、adapter 未通過 gate 不啟用。

## 發佈包裝

P1：

- 不加入模型檔。
- 不加入新 runtime 依賴。
- 實驗設定預設關閉或只在評測工具啟用。

P2：

- 模型為選用下載或獨立包裝。
- 沒有模型也能完整使用輸入法。
- 發佈說明列出模型大小、授權、評測結果、限制。
- 自訓模型需附 manifest 與評測報告。
- 個人 adapter 不得被包進公開 release。
